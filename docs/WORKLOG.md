## 2026-11-02 — LIFF share page, so the operator can send the card as himself

- The Messaging API can only speak as the OA, so "ให้ฉันเป็นคนส่งการ์ดเข้าแชทเพื่อน" has exactly one route on the platform: LIFF `liff.shareTargetPicker()`, which posts up to five message objects into chats the operator picks, in his own name. New `apps/admin/src/LiffSharePage.tsx` serves it at `/share`: it decodes the card from `?c=`, loads the LIFF SDK, `init({liffId})`, refuses to look capable when it is opened outside the LINE app, checks `isApiAvailable('shareTargetPicker')`, and offers `https://line.me/R/msg/text/?…` as the text-only fallback. `chat_message.write` is requested only after LINE reports `PERMISSION_NOT_GRANTED`, followed by a reload, because the token is refreshed on redirect. LINE errors are translated to Thai by code instead of dumping `errorMessage`.
- The card travels in the URL, not the database: `apps/admin/src/liffShare.ts` base64url-encodes the Flex document into the **LIFF** URL (`https://liff.line.me/<id>?c=…`), not the endpoint URL, because LIFF APIs only answer inside that container, and in the query rather than the fragment because the consent redirect drops fragments. `decodeShareCard` re-checks the shape and refuses a card that still holds `{{…}}`.
- The id lives in the server, not the bundle: `GET /api/config` (public, no secrets) returns `LINE_LIFF_CHANNEL_ID`, so registering or replacing the LIFF app is an env edit plus an api restart, not a rebuild. Flex Studio gained แชร์จากมือถือ (LIFF), which prints the link, copies it, and warns in red when the card still contains placeholders.
- LIFF renders the endpoint inside an iframe on `liff.line.me`, which the previous headers forbid. `deploy/nginx.conf` now has its own `location = /share` whose CSP allows `frame-ancestors https://liff.line.me`, `script-src … https://static.line-scdn.net` and `frame-src … https://liff.line.me`; declaring `add_header` there is also what removes the server-wide `X-Frame-Options: DENY`.
- That block did not work on the first deploy and both reasons are now recorded: `try_files $uri /index.html` is an **internal redirect**, so the response was produced by `location /` and the CSP declared for `/share` was thrown away (`curl -I /share` still answered `frame-ancestors 'none'`), and the Caddy edge adds its own `X-Frame-Options: DENY` to every response, which no nginx rule could undo. `/share` now uses `rewrite ^ /index.html break` so it stays in its own location, `connect-src` also allows `https://liff.line.me` for the SDK bridge, and DENY is scoped to `@notshare not path /share /share/*`. Verified against the running host rather than assumed.
- `assertFlexJson` learned the two rules that cost the operator a failed live send: any unreplaced `{{PLACEHOLDER}}` anywhere in the document (including `altText`) and any `uri`/`linkUri` that is not `https://` or `line://`, or `url`/`previewUrl` that is not `https://` — rejected with the JSON path, before LINE answers 400.

Unknown slots are deliberately left in place for the validator to catch.
